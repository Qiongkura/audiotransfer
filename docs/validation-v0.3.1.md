# 0.3.1 主旋律与类型选择验证记录

2026-10-14，在 Windows / Python 3.10、STM32F103C8T6 与 ST-Link 环境验证。

## 类型和主奏路径

- 桌面程序及命令行支持“自动识别 / 有演唱 / 纯音乐”；更换类型会使上一份转换结果失效，需要重新转换。
- 有演唱模式保护整段演唱，可靠主唱音高缺失时保留休止；独立前奏、间奏和尾奏使用乐器路径。
- 纯音乐合回 Demucs 的 vocals 与 other 音轨中的乐器，避免独奏被误分到人声轨后丢失；不合回 bass 和 drums。
- 乐器音符候选来自实际频谱峰。神经结果为匹配的候选提供评分，连续路径减少伴奏与主奏之间的切换。
- 自动选择基于全曲人声轨证据的启发式判断，不是经过标注数据评估的人声分类器；识别不符时可手动选择。

短乐器区段的诊断定义：持续不超过 950 ms，前后最近的主唱区段均相距不足 1.5 秒。修改前约 23、30、34、37、59、66、91 秒等位置出现此类切换；新版保护演唱段后该项降为零。它衡量声部切换，不能当作旋律逐音准确率或听感评分。

本次实际录音未触发新增的弱延音恢复和短八度误识别修复；这两项由合成边界场景检查，不能归因于本首歌的改善。新增 `source-regions.json` 保存声部区段与原始输入时间，便于检查后续音频。

## 检查与实板

Python 自动检查 87 项通过。新增场景包含真实换气保留、5 秒独立间奏、纯音乐主奏落入人声轨、110 Hz 低音独奏、拒绝没有实际频谱峰的混合根音、弱延音与真实静音、短八度误判与真实跳音，以及类型导出和非整跳步的总时长。

新版完整播放器编译通过：Flash 45404 B / 65536 B，RAM 2288 B / 20480 B。当前歌曲通过 OpenOCD 直接写入并返回 `Verified OK`，复位后开始播放；默认音量 50%，暂停键仍为 PA2。

ST-Link 默认连接速度曾出现 `init mode failed`；100 kHz 连接及写入校验通过。新版生成的屏幕播放器在 `platformio.ini` 设置 `debug_speed = 100`，本机 PlatformIO 的 STM32 构建器会将该参数用于 OpenOCD 烧录。

加入该设置后重新生成完整播放器，通过后台调用桌面程序共用的烧录后端，中文路径临时编译、PlatformIO 上传、写入校验及复位均成功。验证没有操作界面中的烧录按钮。

本次未修改 MCU 的按键、OLED 和音量逻辑；此前 52 项 Cortex-M3 检查、实板暂停及音量验证见 [0.3 记录](validation.md)。本次没有人工声学听感评分，也没有以合成检查代替实际复杂纯音乐的逐音评估。
