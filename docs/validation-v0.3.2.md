# 0.3.2 人声基音核验与快速跳音处理

2026-10-14，在当前完整孙燕姿《我怀念的》录音上验证。转换不使用歌曲专用曲谱。

## 改动

- RMVPE 作为默认演唱基音核验模型，结合 CREPE 的可靠唱音。两边都缺少证据的弱片段先留休止，匹配两侧可靠唱音且有实际音高、能量持续的弱延音可保留；真实低能量换气不恢复。
- 人声量化后使用可信度加权的连续音符路径。候选必须在同一人声片段前后 200 ms 内观察到，实际起音降低换音代价。休止与声部边界切断路径，不借用乐器段的音。
- 纯音乐跳过人声模型，继续使用实际频谱峰和 CREPE 评分的主奏路径。
- 原始 RMVPE 网络模块保留 Apache 2.0 许可证与来源说明。权重从固定版本下载，压缩包及权重均校验 SHA-256，通过后才安装；推理用 `weights_only=True` 加载。坏音高缓存重新计算。
- 增加 `--song-backend rmvpe` 默认选项，保留 `crepe` 和 `pyin`。桌面启动不加载模型；首次转换时按需下载，以后离线复用。

## 当前歌曲检查

| 指标 | 0.3.1 | 0.3.2 |
| --- | ---: | ---: |
| 输出事件数 | 1001 | 984 |
| 时长不超过 160 ms 的发声事件 | 325 | 270 |
| 唱段前后夹入的短乐器区段 | 0 | 0 |
| 完整输出时长 | 289067 ms | 289067 ms |

短乐器区段沿用 [0.3.1 记录](validation-v0.3.1.md) 的定义。短音计数包含真实快音，不能把减少的 55 个事件都称为错音，也不能将数量下降当成音准或听感评分。

两个人声模型共同具有高可信度的 94.48 秒中，99.936% 的分析帧相差不到半音。这是模型一致性诊断，没有人工逐音标注；不代表歌曲整体准确率。候选交叉核验先拒绝了 27.82 秒缺乏充分证据的弱音高，其中符合延音及短识别空洞条件的部分会恢复，不能把该数值当作最终休止时长或已证实的错音时长。

实际推理按 12 秒分块，两侧保留 1 秒上下文。完整录音在本机 CUDA 环境转换、导出中文屏幕播放器与完整试听成功，缓存再次使用成功。实际 CPU 推理也验证了 2 秒人声片段，输出 200 个原生分析帧，数值有限。

电脑对比试听取同一原曲 01:35–01:45，顺序为原曲、上一版、新版，每段分别以 1、2、3 声提示音标记，使用一致的响度归一化。试听及原曲留在本机，未上传仓库。未人工评定声学音色或逐音准确率。

## 自动检查和固件

Python 检查 107 项及 3 个时间步长子场景通过。新增检查包含一颗或连续两颗弱突发音、可靠快速连奏、真实短跳音及半音起音、弱延音、换气、声部隔离、频率与能量边界、模型不确定时的保留策略、残缺模型下载拒绝、缓存时间轴及坏缓存恢复。

构建 Python wheel 成功，RMVPE 许可证及来源说明包含在包中，无模型权重或音频文件。默认 MCU 暂停、音量和 OLED 逻辑没有改动，已有实板检查见 [0.3 记录](validation.md)。

完整新版使用后台烧录工具通过 ST-Link 的 100 kHz 连接写入实际 STM32F103C8T6，返回 `Verified OK` 并复位开始播放，未操作界面烧录按钮。开机音量 50%，暂停键 PA2，保留完整歌曲时间线。

本次固件 Flash 45196 B / 65536 B，RAM 2288 B / 20480 B；二进制文件 45504 B，SHA-256 为 `1bf4dc4c356bc316b99293cc3fb4cb7ef6e81daae6dcebf06a3d9f4b039de065`。该歌曲固件留在本机。
