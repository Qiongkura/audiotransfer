# 0.5.0 通用主旋律转换验证

2026-10-15。目标是所有歌曲共用自动提取规则，不再把校对过的一首歌的效果当作通用转换的证明。

## 改动

- 删除桌面转换中的《茶汤》SHA-256 自动校谱入口。六首测试都走 `separate_file → analyze_stems → events_from_song → arrange_events → write_player_project`，没有输入曲谱、歌曲专用参数或手工改音。独立校谱示例保留。
- 演唱与器乐都先用连续音高计算候选代价，再选离散音符。旧路线先取整，失去了“只是颤音越过取整边界”的信息。
- 路径同时约束音符持续时间。默认普通音符持续先验为 80 ms；只有起音、可信度至少 0.85、音高稳定三项都满足时，才接纳 40–60 ms 快音。起音附近的短促辅音误识别不能只凭一次能量变化通过。
- 分析路径在休止、声部变化处断开。移除通用的短事件吸收步骤，保留已确认的短换气，不向另一个声部或跨过休止借音。
- 自动全曲转换保留原始换音时间，不再将边界移到十六分音符网格；拍点仍用于力度。整体移调、连奏、OLED、音量和暂停键保留。
- 可选 GAME 路线改为“有连续主唱证据支持的候选＋清楚基音锚点”。锚点可恢复漏掉的元音、纠正错音及模型吞掉的换音；模型边界不再全部当作重新起音。它仍是试用方式，默认不启用。

## 六首完整录音

对照基线是本轮改动前的 0.4.1 / RMVPE 自动流程。《茶汤》基线也直接调用自动流程，跳过当时桌面的校谱捷径。共用相同分离轨与原始模型输出，默认设置、原速、完整时长。新版通过桌面转换后检查工程清单；六首均判为有演唱。

参考区域要求 CREPE 可信度 > 0.9、RMVPE 可信度 > 0.8、两者音高距离不超过 0.75 半音。先撤销输出的整体移调，再在原曲 20 ms 时间点比较。下表统计输出有声时偏离 RMVPE 超过一个半音的累计秒数，以及参考有声却输出休止的秒数。

这是与转换器共享模型的**一致性诊断，不是独立人工准确率或听感评分**。不确定的主唱、伴唱及多乐器齐奏区域不在高可信度参考中，不能从表格推断它们已被正确识别。半音阈值等更细统计见 [原始汇总](validation-v0.5.0-results.json)；例如《泪海》超过半音的时长从 7.60 s 变为 7.72 s，并非每个指标都改善。

最终总事件数可能增加：保留短换气会拆开原先被错误合并的延音。没有以“短音更少”作为成功条件。实验第一版曾多出不受约束的 20–60 ms 碎音，已在最终版本加入持续时间和快音证据判断。

所有输出精确保持原曲时长，`snapped_boundaries=0`。已生成各歌原曲／旧自动版／新自动版的等 RMS 对照片段，前面分别为 1、2、3 声提示；这些试听保存在本机 I 盘，原录音及生成音频未上传仓库。

## 器乐与回归检查

- 独立指定 24 个 MIDI 主奏音（每音 500 ms），合成 12 秒音频，叠加持续低音和和弦，走桌面“纯音乐”完整分离、主奏提取及播放器生成流程。每音取起音后 120–380 ms 的内部区域，共 312 个时间点，312 个均与预设主奏相差不超过半音；保持精确 12 秒与纯音乐类型。
- 这是可控的合成器乐测试，不代表已验证所有真实纯音乐录音、主奏换手或复杂齐奏。
- 128 项 Python 检查通过，覆盖不同音域及两种声部的颤音、真实 80 ms 快音、可信的 40 ms 起音、辅音前错误低音、20 ms 孤立碎音、40 ms 真换气、声部边界，以及 GAME 锚点恢复漏音和正常连奏。
- 完整《我怀念的》另走可选 GAME 流程，复用原始唱音缓存，生成 1056 个事件、270 处连奏及 543 个连续基音锚点；确认整个新候选核对和导出流程可运行，不据此宣称试用路线听感优于默认。
- Python wheel 构建通过，并检查包含当前源码与许可文件，不包含模型权重或原音频。
- 桌面隐藏窗口检查默认“连续主旋律（默认）”、自动类型与 0.5.0 标题；命令行入口帮助检查通过。
